## 2. Liquid Glass dock (and matching top bar)
Restyle the iPhone tab bar (`AppShell.tsx`, `TabBar`) as Liquid Glass, using the skill picked in step 1:
- a **single** `backdrop-filter` layer with blur and saturation;
- a specular highlight along the top edge, as a soft white gradient;
- a bright inner rim, so the edge reads as thick glass;
- a soft drop shadow, with slight translucency so content tints the glass;
- an active-tab pill that slides between tabs with a spring (`motion`), respecting `prefers-reduced-motion`.

Constraints:
- **Safari-safe:** no SVG refraction or distortion filters in `backdrop-filter`. Safari doesn't support them, so on iPhone they'd silently fall back to plain blur.
- Keep the v1.0 fix: the dock sits on a gradient that fades to the bottom edge, and the viewport re-settles after the keyboard closes (`lib/viewport.ts`). The dock must sit flush at the bottom in the home-screen app.
- Make the top bar match, and both must look right in light, dark and OLED mode (added in v1.1).
- Check scrolling stays smooth with the feed behind the glass.

## 4. Minimal Wardrobe
The Wardrobe page feels clunky: inline name editing, the "bought from" details and so on are all visible on the grid. Make it as minimal as the feed.

**Grid tile** (same look as a feed tile): photo, **brand** (small caps, muted), **item name** (one line, truncated), **value** in £. The value is my custom value if I've set one, otherwise the estimated resale value, otherwise the price I paid. Nothing else: no inline inputs, no visible delete button on the tile. Keep the wardrobe value total at the top, styled minimally.

**Tap a tile** to open a detail sheet in the same style as the listing sheet. It shows everything:
- the photo(s);
- brand and name;
- size and category;
- price paid;
- custom value and estimated value (with "based on N similar listings" and the trend, if there is one);
- **date of purchase**;
- where it was bought (marketplace) and **a link to the original listing**, which opens the marketplace URL;
- note.

**Pencil icon** in the sheet header switches to edit mode: brand, name, size, category, price paid, custom value, date of purchase and note. Save and Cancel go at the bottom. Delete lives in edit mode (or a ⋯ menu) with a confirmation.

**Items bought from Saved** (v1.1 "I bought it"):
- the **date of purchase** is recorded automatically (the day I tapped it, editable);
- the **listing link is kept**, even after the listing goes inactive or is cleaned up;
- if v1.1 didn't store these, add them with a migration and backfill existing bought items where possible.

Items I uploaded myself just have no link or source; the sheet shows only the fields that have values. The Wishlist tab gets the same tile and sheet treatment.

## 5. Performance: smoother and lighter
Measure first. Before changing anything, record a baseline in the browser pane at iPhone size:
- time until the feed's first tiles appear (cold and warm);
- the size of the images downloaded for the first screen;
- whether scrolling stays smooth after loading about 300 tiles.

Then, in this order, re-measuring after each step:
1. **Thumbnails.** Add an API route that serves listing photos as small cached WebP thumbnails (for example 480 px wide, with a 2× version for retina) and use them for feed, saved and wardrobe tiles. The full-size photo loads only in the listing sheet. It must reuse the existing image security in `embeddings/images.py`:
   - host allowlist and public-IP pinning;
   - no redirects;
   - a size cap;
   - only for listings Rack already has.

   Cache the thumbnails on disk with a size limit and clean-up, and send long `Cache-Control` headers.
2. **Instant start.** Cache the last feed and saved responses, so the app opens immediately with the last results while fresh ones load. Use TanStack Query persistence, or let the service worker cache `/api/feed` for the logged-in session only, and clear it on logout. Never cache auth endpoints.
3. **Virtualized grid.** Only render the tiles near the screen (for example with `@tanstack/react-virtual`) so long feeds stay smooth. Infinite scroll, scroll position when coming back from a listing, and the BlurFade entrance on the first screen must keep working.
4. **Prefetch.** Load the next feed page before reaching the end, and the listing's gallery and details when a tile becomes visible or is touched.
5. **Trim.** Check the JS bundle size: code-split the heavier pages and the sheet, and make sure motion/lucide imports are tree-shaken. Remove any unused magicui components.

Show me before and after numbers for each step.
