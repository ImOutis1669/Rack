## 2. Bug: the dock's selection pill doesn't slide between tabs (iPhone)
Tapping Feed → Saved or Hunts → Wardrobe jumps instead of sliding. Likely cause, already spotted:
`TabBar` is rendered inside each page's `PageShell`, so the whole dock is rebuilt on every
navigation and the pill (`layoutId="dock-pill"`) has nothing to animate from. Move the dock (and
the desktop segmented tabs) to app level so it persists across routes, then make sure the pill
slides with the default spring and is instant with reduced motion. Lazy pages must not make the
dock flicker while a page loads.

## 4. Swipe down to close sheets
Every sheet (listing sheet with "Buy on…", filters, I bought it, wardrobe item, hunt form, sources…)
should close when I drag it down, like iOS:
- follow the finger 1:1 from the grabber/header, and from the content when it's scrolled to the top;

Build it once in the shared `Sheet` component.

## 5. Sharper eBay photos
eBay photos look very low quality. Root cause found in the database: **1,891 of ~1,970 eBay
listings store their photo as `…/s-l225.jpg`, a 225 px image** that the search API returns, which
Rack then stretches into 640 px tiles. Fix the quality without giving back the v1.1 performance
gains:
- use the larger eBay size for tiles and sheets (eBay's CDN serves size variants such as
  `s-l500`, `s-l960`, `s-l1600`; confirm what the API itself offers, e.g. `getItem` images or
  documented `image` fields, before relying on URL rewriting), fix it at ingest and backfill
  existing rows, and invalidate their cached thumbnails;
- then review the thumbnail settings for every source (WebP quality 78, widths 480/640/960,
  resampling) and pick the best quality-for-size trade-off with real before/after numbers and
  side-by-side screenshots at iPhone size. Consider a higher quality or AVIF if Safari supports it.
- Measure the first-screen photo bytes against the v1.1 numbers in `docs/perf-v1.1.md`.
