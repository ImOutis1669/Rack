## Decisions already made (17 November 2026)
- **Friends get their own accounts on my server, by invitation only** (no open sign-up). Each
  friend has their own taste, designers, sizes, wardrobe/wishlist, Saved, votes, hunts, hidden
  sellers/brands and alerts. Listings, photos and their embeddings stay shared (one crawler).
- **Friends use the web app only** (Safari / Add to Home Screen, or a desktop browser). The iOS
  app stays mine (sideloaded). No TestFlight, no paid Apple developer account for now.
- **The server stays on this Windows PC** (Docker Desktop) for now. I may build a dedicated
  server PC later: keep everything portable, and write the move down, but don't do it.
- **Public access through Cloudflare Tunnel** from this PC (the compose profile `tunnel` and
  `.env.tunnel` already exist), because friends aren't on my tailnet. I keep using Tailscale.
- **iOS app: every tab's title sits inline in the header row**, left, in line with the glass
  button group, like Grailed's logo (no iOS large titles): "Rack" on the feed, "Hunts",
  "Saved", "Wardrobe". Content scrolls under the transparent bar.

## Constraints
- **Security first.** Every request must only ever see its own user's data. Keep every
  guarantee of the 2026-11-16 audit (login rate limits incl. the global cap, session epochs,
  "log out everywhere", password-change invalidation, CSRF for cookies, bearer tokens for the
  app, no secrets in logs, security headers, SSRF guards) and make them per user. Being public
  on the internet (not tailnet-only) raises the bar: brute force, enumeration, invite guessing.
  Finish with a full audit pass using `docs/security-audit-prompt.md`, with IDOR tests for
  every endpoint (user A can't read or change user B's anything).
- **Privacy.** Friends' wardrobe photos, passwords and taste live on my PC: a short plain
  privacy note in the app, "delete my account" (removes everything theirs), and no tracking.
  The eBay rule stays: no eBay user data stored (`CLAUDE.md`), for every user.
- **Marketplaces see the same load.** One shared crawler keeps today's rate limits (>= 10 s per
  request per source, honest UA, no proxies or evasion). Users' designers and categories merge
  into one search plan; more users means each search comes round less often, not more traffic.
  eBay's 5,000 searches a day are shared: cap hunts per user and show usage to the owner.
- **The owner's existing data becomes the owner account's data**, with no loss (migration
  tested on a copy of the real database first). My iOS app keeps working (log in again at most).
- Licences as above; nothing licensed in the repo (public).

## Steps

### 0. Plan
- List every single-user assumption: the `profile` row with fixed id 1 (`store.PROFILE_ID`),
  `RACK_PASSWORD_HASH` in env, the global session epoch in `app_state['auth']`, tables without
  an owner (`profile`, `designers`, `adjacent_designers`, `taste_items`, `listing_scores`,
  `feedback`, `saved`, `hidden`, `seen`, `hunts`, `hunt_matches`, `notifications`,
  `push_subscriptions`, `estimate_snapshots`, the planner/scoring state in `app_state`), global
  notification settings in `.env`, worker jobs that assume one profile (scoring, hunts, price
  drops, resale/sold prices, ebay retention), and the web/app screens that assume one user.
- Propose the data model (a `users` table; owner columns; what stays shared), the migration,
  and how scoring scales (per-user scores, only for active users, incremental).
- Map every endpoint to who may call it (owner, any user, nobody unauthenticated).

### 1. Users and login (backend)
`users` (username, argon2 hash, role owner/friend, created, disabled, per-user session epoch and
password fingerprint). The owner account is created from the current `RACK_PASSWORD_HASH`.
Login by username + password (cookie for the web, bearer token for the app), rate limits per IP,
per username and the global cap; no "user exists" leaks. Change password; per-user "log out
everywhere". Invites: single-use, expiring codes or links the owner creates and can revoke;
sign-up needs a valid invite. Owner: list users, disable, delete. Tests in the style of
`tests/test_security.py` and `tests/test_app_token.py`.

### 2. Per-user data and ranking
Owner column on every personal table, every query scoped to the current user (a helper that
makes forgetting it hard), migrations, and the owner's data moved over. Shared: listings,
images, embeddings, sold listings, source health. Ranking per user (the planner merges all
users' searches under the existing limits); hunts, saved-price checks, estimates and alerts per
user, with caps. The eBay retention job also clears every user's votes/saves on deleted eBay
listings.

### 3. Alerts per user
Each user sets their own ntfy topic or Telegram chat (the bot token stays server-wide) and their
own Web Push subscriptions; test alert per user; recent alerts per user.

### 4. Web app
Login with username; sign-up page from an invite link; account page (change password, log out
everywhere, delete account); privacy note; owner-only admin (invites, users, Sources, eBay
usage). The font/icon decision from above for friends.

### 5. iOS app
Username on the login screen; token migration. **Inline titles on every tab** (header-row title
left, glass button group right, no large titles; content scrolls under the bar; Reduce
Transparency / contrast still readable; check light and dark). Owner bits stay; nothing for
friends (they use the web).

### 6. Public access from this PC
Cloudflare Tunnel (`docker compose --profile tunnel up -d`) to my hostname; the API stays bound
to 127.0.0.1; `RACK_TRUSTED_PROXIES` for cloudflared; Cloudflare rate-limit/WAF rules for
`/api/auth/*`; `RACK_COOKIE_SECURE=true`; a strong owner password; CORS stays closed. Step-by-step
for me (Cloudflare dashboard, tunnel token in `.env.tunnel`, DNS), plus how to check it from
outside my network. Write `docs/server-move.md` for later (dedicated server PC: Linux + Docker,
`pg_dump`/restore, the data dir, the `.env*` files, tunnel, nightly backups) without doing it.

### 7. Security pass
Run `docs/security-audit-prompt.md` against the multi-user version; fix and test every finding.
